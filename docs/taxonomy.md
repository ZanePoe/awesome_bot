# 范围与分类

## 工作定义

主动式 Agent 能在没有一条新的用户指令时，因计划、外部变化、持续目标或环境观察而开始一轮判断；在明确的授权范围内调用工具、保持状态，并决定是否向人反馈。可使用本地电脑、容器、远程电脑或 API，不以“拥有整个电脑的无限权限”为门槛。

完整助手的纳入检查：公开可定位的实现；可指认的非手动触发机制；真实工具或信息服务输出；可持续的任务状态、记忆或会话。只有营销中的 autonomous、只有后台 worker、只有手动工具调用，都不足以自动进入核心推荐。

## 两条独立分类轴

第一条是项目在系统里的位置。每个项目只有一个主类别，避免跨分类重复统计。

| 类别 | 判定问题 | 代表种子 / 项目 |
| --- | --- | --- |
| 常驻个人助手与轻量运行时 | 能否直接作为长期使用的个人助手运行？ | nanoMuse、Rakazo、OpenClaw |
| 工作空间与上下文助手 | 是否以项目环境、屏幕观察或工作流为中心？ | PilotDeck、MineContext |
| 主动插件与调度扩展 | 是否主要为已有 Agent 提供 Bot、唤醒或调度能力？ | DS Bot、dsh-proactive、murmur |
| Harness 与持久运行基础 | 是否提供可供上层应用编排的 Agent 执行基础？ | Pi、DeepSeek Harness、Letta Code |
| 电脑与浏览器控制组件 | 是否主要提供外部环境操作能力？ | Windows-MCP、Browser Use |
| 研究实现与评测代码 | 是否主要用于复现实验、训练或评测？ | ProactiveAgent、π-Bench、OSWorld |
| 历史与迁移项目 | 官方是否宣布不再维护，且存在迁移价值？ | LettaBot |

第二条是触发机制：固定时间 / cron、周期 heartbeat、事件 / webhook、上下文需求推断、长期目标继续执行、或需要外接触发器。多个机制可以同时存在。

`core` 表示主动机制已文档化；`adjacent` 表示相邻能力或主动触发待核验；`research` 表示研究用途；`historical` 表示历史参考。它们是目录标签，不是质量等级。

## 五个参考项目得到的边界

- [nanoMuse](https://github.com/nano-muse/nanoMuse)：个人记忆、后台目标与跨设备执行。
- [Rakazo](https://github.com/elie222/rakazo)：持久 Bot、记忆、routines 与电脑环境。
- [PilotDeck](https://github.com/OpenBMB/PilotDeck)：按工作空间组织长期任务和后台工作。
- [DS Bot](https://github.com/Fei2411/DS-Bot)：持久 Bot 与 harness 插件；首页未确认独立调度，不将“长期存在”直接认作“主动发起”。
- [Windows-MCP](https://github.com/CursorTouch/Windows-MCP)：执行层组件。能控制电脑并不意味着自行感知任务或定时唤醒。

这些判断的固定提交来源见 [项目详表](projects.md)。核心清单允许新项目低 star 入选，不设一千 star 等硬性流量门槛。

## 排除与保留

纯聊天界面、没有具体实现的概念页、普通定时脚本、仅提供模型权重，以及与个人/数字环境主动交互无关的机器人导航或游戏合作，不进入核心助手榜。商业闭源 Muse、Grok Bot 仅作为检索参照，不伪装成开源条目。

论文可收录相邻的长期记忆、电脑执行和模拟 Agent 基础研究，但必须写明边界。研究源码许可不明或含非商业限制时，只作为研究线索，不标成已核验开放许可证的项目。

## 可实测的行为层级

这是一套后续测试标签，首版未实际为项目打这些能力分：

1. **按需执行**：有明确指令时能完成单次工具任务。
2. **自主唤醒**：用户不再发消息时，预设时间或事件能触发工作。
3. **条件介入**：同样触发下，有事执行/通知，无事保持静默。
4. **持续目标**：跨多次唤醒保留状态，推进目标并能处理失败与暂停。

通过第 4 层不意味着第 1 层任务成功率更高，层级不能代替具体场景测评。
